# دليل Browser Use Cloud API V4 — المرجع المختصر لمهارة Nimna

> النسخة الكاملة (Quick start + تعليمات الوكيل الحرفية) في [`docs/browser_use_v4.md`](../../docs/browser_use_v4.md).
> هذا الملف خلاصة تشغيلية: القواعد التي يجب ألا تُخترق عند كتابة أي تكامل.

## 1. اختيار الإصدار والاستيراد

| الحالة | الخيار |
|---|---|
| تكامل وكلاء جديد | **API V4** — استيراد صريح: `from browser_use_sdk.v4 import BrowserUse` / `import { BrowserUse } from "browser-use-sdk/v4"` |
| مهام بسيطة منخفضة الكلفة | V2 (أرخص) |
| أمثلة V3 قائمة | تبقى صالحة لكن **موثّقة بالإصدار صراحةً** |
| مكتبة open-source `browser-use` | واجهة مختلفة تمامًا عن `browser-use-sdk` المستضاف — لا تخلط الأمثلة |

- الحقول الجديدة التي يتأخر فيها تعريف أنواع الـ SDK: استخدم مخطط REST العام (OpenAPI) ولا تخترع دعمًا في الـ SDK.
- قبول الـ API وظهور الحقل في اللوحة وتوفره لدى المزود ثلاثة أمور منفصلة.

## 2. المصادقة

```bash
export BROWSER_USE_API_KEY=your_key
```

- الترويسة: `X-Browser-Use-API-Key: $BROWSER_USE_API_KEY` — **بدون** بادئة `Bearer`.
- لا يُكتب المفتاح في الكود ولا في مخرجات المهارة؛ يُقرأ من البيئة فقط.
- قبل تشخيص أي نقص رصيد: تأكد من **مشروع** مفتاح الـ API (المفاتيح في مشروع واحد تتشارك السعة والأرصدة).

## 3. دورة حياة المتصفح (أهم قاعدة تشغيلية)

- اكتمال التشغيل، أو إغلاق اتصال CDP، أو انتهاء مهلة الانتظار لدى العميل — **لا شيء منها يوقف المتصفح السحابي**.
- أوقف كل متصفح بدأته، داخل `finally` دائمًا، حتى عند فشل الاتصال أو التنقل:

```python
finally:
    client.browsers.stop(session.id)
```

```bash
PATCH /api/v4/browsers/{id}
{"action": "stop"}
```

- مهلة الانتظار لدى العميل **لا تُلغي** التشغيل على الخادم — قد يستمر ويسلّم نتيجة؛ طابق الأثر الخارجي قبل تكرار العمل.
- التوقيتات منفصلة: مهلة سحابية ≠ مهلة عميل الـ API ≠ مهلة النموذج ≠ اكتمال المهمة.

## 4. التزامن ومعدل الطلبات

**مصدر الحقيقة للسعة:** `GET /api/v2/billing/account` → `projectId`, `concurrentSessionLimit`, `activeSessionCount`, رصيد الحساب. (حتى مع V4). حقل `rateLimit` اسم قديم (legacy) لحد التزامن — **ليس** طلبات/ثانية.

- احتفظ بأعلى منحة سارية: المنحة الحالية / خطة legacy / فئة الإنفاق. فئات الإنفاق الحالية: 10 / 50 / 250 / 500 / 1000 مقابل دفعات مؤهلة $0 / $100 / $1000 / $5000 / $25000. المشاريع المفوترة خارجيًا قد تختلف — اعتمد حد الحساب.
- حدود HTTP طبقتان تُحسبان بشكل مستقل:
  - **حواف WAF العامة:** منذ 9 سبتمبر 2026 — 1000 RPS لكل IP عام للزيارات العامة، و2500 RPS لكل IP لقراءات الحالة المختارة، تُقاس على نافذة 300 ثانية.
  - **ميزانية لكل مشروع:** الزيارات العامة (بما فيها أحداث V4 وقراءة التشغيلات الكاملة) افتراضيًا `max(25, 2×التزامن المخزّن)` بحد أقصى 100 RPS؛ قراءات الحالة المختارة افتراضيًا `max(25, 2×التزامن)` بلا حد أقصى. التجاوزات الخاصة بالمشروع وقواعد الحواف الخاصة بالحساب ممكنة.
  - كل مفاتيح المشروع تتشارك ميزانيته؛ ومن يتشارك معك IP العام يتشارك سعة الحافة.

### نافذة الـ 5 ثوانٍ (مصيدة شائعة)

`X-RateLimit-Limit=125` تعني **125 طلبًا لكل نافذة خمس ثوانٍ ≈ 25 RPS** — وليس 125 RPS.

- خنق المشروع يعيد `limit_rps` و`retry_after_seconds`؛ خنق الحافة قد يعيد `Retry-After: 300` بلا `limit_rps`. **التزم بـ `Retry-After` المُعاد دائمًا.**
- ممارسات آمنة: عدد عمال محدود، تباعد استطلاعات الحالة، استنزاف صفحات الأحداث (`hasMore`) بعد الحالة النهائية.
- جلسة V4 مشغولة تعيد **409**؛ طابورها يستوعب 20 رسالة معلّقة وهو **ليس** طابور دفعات على مستوى المشروع.

## 5. الفوترة

- السحابة **pay-as-you-go** — لا تقترح على أحد شراء اشتراك جديد لتفعيل proxies مخصصة أو BYOK. تمويل الاستخدام وأهلية النماذج يبقيان ساريين. BYOK يفوتر توكنات المزود على حدة، وBrowser Use يفوتر التنسيق + استخدام المتصفح/الشبكة.
- رصيد التسجيل منحة **لمرة واحدة**؛ رصيد الشراء الإضافي لا ينتهي. حدود الإنفاق الشهرية للمفتاح **حدود مرنة** وليست محفظة مسبقة الدفع — عمل متزامن أو جارٍ قد يتجاوزها.
- إعادة الشحن التلقائي لها مبلغا **تشغيل** و**شراء** منفصلان، وقد يخصم فورًا عند التفعيل تحت العتبة. الأسعار الحالية: https://browser-use.com/pricing
- **Box وBux موقوفان** — لا توصِ بـ SDKs حصص sandbox أو خطط اشتراك خاصة بهما.

## 6. الجلسات وworkspaces وprofiles

- جلسة V4 تحمل **سجل المحادثة**، وworkspace يحمل **الملفات**، وprofile يحمل **حالة المتصفح**. هذه المعرفات ومساحات أسماء workspaces (V3/V4) **غير قابلة للتبادل**.
- V4 يستعيد ملفات الـ workspace المرفوعة تلقائيًا؛ المرفقات المُجهَّزة تبقى متاحة لمتابعات الجلسة.
- تسلسل (serialize) التشغيلات التي تكتب ملفات مشتركة، وانتظر الاكتمال قبل قراءة المخرجات.

## 7. التسجيل (Recording) والمعاينة

- التسجيل عبر الـ API **مطفأ افتراضيًا**: `enableRecording` لإنشاء متصفح مستقل، أو `browserSettings.record` لتشغيل وكيل.
- أوقف المتصفح وامنح وقتًا لمعالجة الفيديو غير المتزامنة؛ توقف عن الاستعلام عندما تصبح `recordingAvailable` تساوي `false`. المعاينة الحية للمتصفح النشط فقط.
- إيقاف المتصفح ≠ حذف جلسة ≠ أرشفة workspace ≠ حذف ملفات — آثار مختلفة.

## 8. إعدادات التفكير للنماذج (Reasoning)

| النموذج | القيم الصالحة | الافتراضي |
|---|---|---|
| `GPT-6 Astra` | `low`, `medium`, `high`, `xhigh`, `max` | `xhigh` |

- غير صالح لـ GPT-6 Astra: `none`, `minimal`.
- القيم خاصة بكل نموذج — لا تعمّم.

## 9. نتائج open-source والموثوقية

- في open-source: `is_done` تعني فقط تنفيذ أمر إنهاء (`done`) صريح. `is_successful` هي **رأي الوكيل نفسه** بالنتيجة — تحقق من الأفعال الخارجية المهمة (طلبات، مدفوعات، إرسال) بمصدر مستقل.
- متصفح مُدار جديد **لا يضمن** IP بروكسي فريدًا أو مدينة معينة.
